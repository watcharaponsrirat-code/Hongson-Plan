# Hongson Plan

เปิดเว็บทดลอง: **https://watcharaponsrirat-code.github.io/Hongson-Plan/**

มีสองวิธีเปิดใช้งาน: **พื้นที่ทำงานบน GitHub Pages** ใช้ `index.html` ที่รากโปรเจกต์ เก็บข้อมูลแยกในเบราว์เซอร์ ตั้งชื่อผู้ดำเนินงานและเลือกบทบาทได้โดยไม่มีรหัสผ่าน ดู [วิธีอัปโหลดและใช้งาน GitHub Pages](GITHUB_PAGES.md) ส่วน **ระบบ Node.js/SQLite** ใช้บัญชีพร้อมรหัสผ่านและตรวจสิทธิ์บนเซิร์ฟเวอร์ ตามขั้นตอนด้านล่างและใช้หน้าเริ่มต้น `public/index.html` การนำไฟล์ใน `public/` ไปอัปโหลดอย่างเดียวไม่ทำให้ระบบเซิร์ฟเวอร์ทำงานบน GitHub Pages

ระบบงานแผนและงบประมาณในเครื่อง เก็บข้อมูลด้วย SQLite และเปิดผ่านเบราว์เซอร์ที่ `http://127.0.0.1:4310` มีแบบเขียนโครงการ 19 หัวข้อ ตาราง SOPAA ตารางประเมินผล และหน้าพิจารณาตามไฟล์โรงเรียนที่ได้รับ รุ่นซอร์สปัจจุบันเพิ่มการตั้งค่าผู้ดูแลครั้งแรก บัญชีราคาวัสดุจากไฟล์โรงเรียน และตัวเลือกช่วยกรอกโครงการ การแก้ซอร์สในเครื่องยังไม่ทำให้เว็บ GitHub Pages เปลี่ยนจนกว่าจะอัปโหลดและเผยแพร่สำเร็จ

หน้า **ภาพรวมงานแผน** กรองปีงบประมาณ กลุ่มงาน และค้นหาชื่อกิจกรรม/ผู้รับผิดชอบได้ พร้อมเลือกสถานะโครงการ เปิดคิวรอพิจารณาตามบทบาท และเรียงงานเลยกำหนดไว้ก่อน ยอดเงินรวมใช้ปีและกลุ่มงานจากฉบับอนุมัติล่าสุด โดยคำค้นและสถานะไม่เปลี่ยนยอดเงิน ปุ่มเปิดงานพาไปยังโครงการ คำขอ สรุปผล หรือแบบบันทึกจ่ายที่เกี่ยวข้อง

## เริ่มใช้งานจาก GitHub

ติดตั้ง Node.js 24 ขึ้นไป ดาวน์โหลดหรือ clone repository แล้วเปิด Terminal ในโฟลเดอร์โปรเจกต์:

```sh
npm start
```

เปิด `http://127.0.0.1:4310` เมื่อฐานข้อมูลยังไม่มีบัญชี ระบบจะให้สร้างผู้ดูแลคนแรกด้วยชื่อ–นามสกุล ชื่อผู้ใช้ และรหัสผ่าน 12–200 ตัวอักษร ชื่อผู้ใช้ใช้ตัวอักษรอังกฤษ ตัวเลข `_` `.` `-` ยาว 3–40 ตัว จากนั้นเพิ่มบัญชีและกำหนดบทบาทในเมนู **ผู้ใช้ / ข้อมูลอ้างอิง** ผู้ดูแลไม่ได้มีสิทธิ์เขียนหรือตรวจอนุมัติโครงการโดยอัตโนมัติ ให้เพิ่มบทบาทที่จำเป็นให้บัญชีนั้น หรือสร้างบัญชีบุคลากรแยกกัน

โปรแกรมสร้างฐานข้อมูลใน `data/` ให้อัตโนมัติ โดยฐานข้อมูลใหม่ไม่มีบัญชีรหัสผ่านร่วม โครงการตัวอย่าง หรือราคาแต่งขึ้น หากมีฐานข้อมูลจากรุ่นก่อน ระบบเก็บบัญชี โครงการ และประวัติเดิมไว้และแสดงหน้าเข้าสู่ระบบตามปกติ ให้ใช้บัญชีเดิมและปรับรหัสผ่าน/สิทธิ์จากเมนูผู้ใช้ ไม่ต้องลบฐานข้อมูลเพื่อตั้งค่าใหม่ กด `Ctrl+C` เพื่อหยุดเซิร์ฟเวอร์ โปรเจกต์ใช้โมดูลที่มากับ Node.js จึงไม่ต้องติดตั้ง npm dependencies เพิ่ม

ระบบ Node.js/SQLite ใช้ `public/school-reference-data.json` เมื่อมีไฟล์ในเครื่อง มิฉะนั้นใช้สำเนาสำหรับเผยแพร่ `public/school-reference-data.pages.json` เช่นเดียวกับ GitHub Pages ครบ 207 หัวข้อจากเอกสารโรงเรียน 8 ไฟล์ รุ่น `school-9e29c67576f7d07a` ส่วน `public/school-reference-data.example.json` เก็บไว้สำหรับชุดทดสอบที่เลือกใช้ข้อมูลสมมติโดยตรง ไฟล์อ้างอิงเฉพาะเครื่องและเอกสารต้นฉบับใน `references/` ถูกยกเว้นจาก Git

Windows สามารถดับเบิลคลิก `Start-Hongson.cmd` ได้เช่นกัน ตัวเปิดแอปใช้ Node.js ที่ติดตั้งในเครื่องเมื่อไม่มี `.runtime/node.exe`

## อัปเดตโค้ดบน GitHub

1. แตกไฟล์ `Hongson-Plan-source.zip`
2. เปิด repository เดิมที่ https://github.com/watcharaponsrirat-code/Hongson-Plan แล้วอัปเดตไฟล์และโฟลเดอร์ภายใน ZIP รวม `.gitignore` โดยให้ `package.json` และ `index.html` อยู่ที่รากของ repository ไม่ต้องสร้าง repository ใหม่
3. บันทึกการเปลี่ยนแปลงบน branch `main` แล้วรอ **pages build and deployment** สำเร็จก่อนเปิดเว็บทดลอง หากต้องการรันระบบ Node.js/SQLite ให้ทำตามวิธีด้านบน

ZIP รวมซอร์สโค้ด ชุดทดสอบ คู่มือ ข้อมูลอ้างอิงตัวอย่าง สำเนารายการอ้างอิงโรงเรียน บัญชีราคาวัสดุ และไฟล์ราคาสำหรับดาวน์โหลดใน `public/downloads/` ส่วนฐานข้อมูลที่ใช้งานอยู่ ไฟล์บันทึก เอกสารใน `references/` และโปรแกรมใน `.runtime/` เก็บไว้เฉพาะเครื่อง การเปิดระบบ Node.js/SQLite ยังต้องมีเครื่องที่รันเซิร์ฟเวอร์ Node.js ส่วนเว็บ GitHub Pages เปิดผ่านเบราว์เซอร์ได้ทันที

สร้าง ZIP ใหม่จากโค้ดปัจจุบันด้วย PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-source.ps1
```

ไฟล์จะอยู่ใน `dist/` สคริปต์รวมเฉพาะรายการซอร์สโค้ดที่กำหนดไว้ หากเพิ่มไฟล์ชนิดใหม่ให้ตรวจรายการในสคริปต์ก่อนจัดชุดส่งมอบ

## เปิดใช้งาน

1. เปิดโฟลเดอร์โปรเจกต์ แล้วดับเบิลคลิก `Start-Hongson.cmd`
2. เมื่อเบราว์เซอร์เปิด ให้สร้างผู้ดูแลครั้งแรก หรือเข้าสู่ระบบด้วยบัญชีที่มีอยู่ ให้ผู้ดูแลเพิ่มบัญชีพร้อมบทบาท **ครู** สำหรับเขียนโครงการ
3. เข้าบัญชีที่มีบทบาทครู เลือก **เขียนโครงการ** กรอกข้อมูลและรายการทรัพยากร แล้วบันทึกฉบับร่าง เปิดรายการที่บันทึกและกด **ตัวอย่างโครงการ** เพื่อพิมพ์หรือบันทึก PDF
4. ใช้ปุ่ม **ทรัพยากรไม่มียี่ห้อ** สำหรับเอกสารแนบเล่มแผน หรือ **ทรัพยากรมียี่ห้อ** สำหรับพัสดุ ส่วนฉบับที่อนุมัติแล้วเปิดจากประวัติและกด **พิมพ์ฉบับอนุมัตินี้** ได้

ตัวเปิดแอปใช้ Node.js ที่ `.runtime\node.exe` หากไม่มีไฟล์นี้ต้องมี Node.js 24 ขึ้นไปในเครื่อง การเปิดซ้ำจะใช้เซิร์ฟเวอร์เดิมเมื่อกำลังทำงานอยู่

บันทึกร่างได้แม้ยังไม่ครบ เมื่อส่งตรวจ โครงการที่สร้างด้วยแบบใหม่ต้องมีข้อมูลหลัก ขั้น SOPAA ครบ 5 ขั้น และตัวชี้วัดพร้อมวิธีประเมิน/เครื่องมืออย่างน้อย 1 รายการ แต่ละขั้น SOPAA เพิ่มกิจกรรมได้หลายรายการ

แบบโครงการมีตัวเลือกปี ภาคเรียน ไตรมาส และเดือน พร้อมคำแนะนำชื่อบุคลากร กลุ่มงาน หน่วยนับ และตำแหน่งผู้ลงนาม ช่องคำแนะนำยังพิมพ์ค่าเองได้ และค่าที่บันทึกไว้เดิมยังแสดงเมื่อเปิดแก้ไข

## บัญชีราคาวัสดุ

แท็บ **รายการทรัพยากร** ค้นหาชื่อวัสดุหรือรายละเอียด กรองหมวดเครื่องเขียน/ราคาหมึก เลือกรายการ แล้วกด **เพิ่มจากบัญชีราคา** ระบบเติมชื่อ คุณลักษณะ หน่วย และราคาให้ ตรวจจำนวน แหล่งเงิน และเดือนใช้เงินก่อนบันทึก ยังเพิ่มรายการเองหรือแก้ราคาที่ใช้กับโครงการได้

บัญชีใน `public/material-catalog.json` มาจากไฟล์ `ราคาเครื่องเขียน 2569 (2).xlsx` รวม 790 ตัวเลือกราคาที่เป็นตัวเลข แยกหมึกแท้และหมึกเทียบเท่า อีก 21 ตัวเลือกที่ต้นฉบับให้ราคาไม่ชัดเจนเก็บข้อความเดิมไว้และไม่เสนอราคาอัตโนมัติ ให้ตรวจรุ่นจากไฟล์ต้นฉบับก่อนเพิ่มรายการเอง ดาวน์โหลดไฟล์ได้จากปุ่มในแท็บทรัพยากร หรือ `public/downloads/material-prices-2569.xlsx`

ทรัพยากรที่เลือกจากบัญชีเก็บราคาที่ใช้และสำเนาที่มาของราคาไว้กับโครงการ รวมรุ่น ไฟล์ ชีต แถว คอลัมน์ และแฮชต้นฉบับ การแก้บัญชีราคาภายหลังไม่เปลี่ยนรายการเดิมหรือเอกสารฉบับอนุมัติ ราคาชุดนี้เป็นราคาตามไฟล์ปี 2569 ไม่ใช่ราคาที่ดึงสดจาก Google Sheets

หากไม่เปิดอัตโนมัติ ให้เปิด PowerShell ในโฟลเดอร์โครงการแล้วรัน:

```powershell
node server.mjs
```

จากนั้นเปิด `http://127.0.0.1:4310` ด้วยเบราว์เซอร์ คงหน้าต่าง PowerShell ไว้ระหว่างใช้งานและกด `Ctrl+C` เพื่อหยุดเซิร์ฟเวอร์ที่เปิดด้วยคำสั่งนี้ หากเริ่มจากตัวเปิดแอปแล้วเกิดข้อผิดพลาด ดู `logs\server-error.log`

หากเซสชันหมดอายุ ระบบจะแสดงหน้าเข้าสู่ระบบแทนส่วนหัวผู้ใช้เดิม แบบฟอร์มที่ยังกรอกอยู่จะเก็บไว้ชั่วคราวในแท็บเดิม เมื่อเข้าสู่บัญชีเดิมและยังมีสิทธิ์เดิมจะกลับมากรอกต่อได้ ให้ตรวจทานและกดบันทึกอีกครั้ง ระบบไม่ส่งคำสั่งเดิมซ้ำอัตโนมัติ การรีเฟรช/ปิดแท็บ การออกจากระบบเอง หรือการเปลี่ยนบัญชีจะไม่เก็บแบบฟอร์มชั่วคราวนี้ หากบันทึกสำเร็จก่อนเซสชันหมดอายุ ระบบจะแจ้งให้เข้าสู่ระบบเพื่อดูข้อมูลล่าสุด

## แชร์ลิงก์ทดลองผ่านอินเทอร์เน็ต

ดับเบิลคลิก `Start-Hongson-Share.cmd` รอจนเปิดเบราว์เซอร์ หากเป็นฐานข้อมูลแชร์ใหม่ ให้ตั้งค่าผู้ดูแลและเพิ่มบัญชีผู้ร่วมทดสอบก่อน จากนั้นคัดลอก **ลิงก์เต็มจาก `logs\share-url.txt`** ส่งให้ผู้ทดลอง ต้องมีส่วน `#key=...` ติดไปด้วย ลิงก์ในแถบที่อยู่จะถูกลบรหัสออกหลังเปิดสำเร็จ จึงไม่ควรคัดลอกจากแถบที่อยู่ ผู้ที่มีลิงก์เต็มเข้าถึงหน้าเข้าสู่ระบบได้ แล้วใช้บัญชีที่ผู้ดูแลจัดเตรียมให้

- เครื่องนี้ต้องเปิดอยู่ ไม่เข้าโหมดพัก และต่ออินเทอร์เน็ต ระหว่างแชร์จะมีโปรแกรมทำงานเบื้องหลัง
- หยุดแชร์ด้วย `Stop-Hongson-Share.cmd` ลิงก์เดิมจะหยุดทำงาน เมื่อเริ่มแชร์รอบใหม่จะได้ลิงก์ใหม่
- โหมดแชร์ใช้ฐานข้อมูลแยกที่ `data\hongson-share.sqlite` ข้อมูลที่ผู้ทดลองบันทึกจะอยู่ร่วมกันในไฟล์นี้และยังอยู่เมื่อเริ่มแชร์ครั้งต่อไป ข้อมูลใน `data\hongson-demo.sqlite` ของการเปิดในเครื่องไม่ได้ถูกนำไปแชร์
- บัญชีของฐานข้อมูลแชร์แยกจากฐานข้อมูลในเครื่อง การรู้ลิงก์ไม่แทนการเข้าสู่ระบบหรือเพิ่มสิทธิ์ของบัญชี หากอัปเกรดฐานข้อมูลแชร์จากรุ่นเก่า บัญชีทดลองเดิมยังอยู่จนกว่าผู้ดูแลจะเปลี่ยนรหัสผ่านหรือปิดบัญชี
- มีการตรวจรหัสในลิงก์ก่อนส่งหน้าจอหรือ API ของระบบ และใช้ HTTPS พร้อมคุกกี้ HttpOnly/Secure

ใช้ [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) ซึ่งเป็นลิงก์ชั่วคราวสำหรับทดลอง ไม่มีการรับประกันความต่อเนื่องของบริการ การแชร์บน Windows ต้องเตรียม `cloudflared.exe` ไว้ใน `.runtime` โดยดาวน์โหลดจาก [แหล่งทางการ](https://developers.cloudflare.com/tunnel/downloads/) โปรแกรมนี้ไม่รวมในชุดซอร์สโค้ดและไม่ได้ติดตั้งเป็น Windows service

## ข้อมูลและขอบเขต

ข้อมูลของระบบในเครื่องอยู่ที่ `data\hongson-demo.sqlite` และไฟล์ประกอบของ SQLite ในโฟลเดอร์เดียวกัน การปิดเบราว์เซอร์ไม่ลบข้อมูล เอกสารต้นฉบับในเครื่องผู้พัฒนาอยู่ใน `references` และไม่ได้รวมทั้งโฟลเดอร์ในชุดซอร์สโค้ด เช่นเดียวกับรายงานตรวจเอกสารใน `reference-review` ลิงก์ไปยังรายงานเหล่านี้จะเปิดได้เฉพาะเครื่องที่มีไฟล์ ส่วนไฟล์ราคาที่จัดไว้สำหรับดาวน์โหลดใน `public/downloads/` รวมในชุดส่งมอบ

รายการข้อ 3–4 และ 6–11 ใช้รายการอ้างอิงโรงเรียนตามแหล่งข้อมูลข้างต้น ข้อ 3 เลือกจาก dropdown และข้อ 4 เติมกลยุทธ์ที่สัมพันธ์กันอัตโนมัติ ข้อ 6–11 แสดงช่องติ๊กจัดกลุ่มตามหัวข้อหลัก ติ๊กหัวข้อหลักแล้วเห็นข้อย่อย เลือกหรือยกเลิกแล้วอัปเดตทันทีโดยไม่ต้องกดเพิ่ม ข้อความแสดงเต็มและบันทึกพร้อมโครงการ มีช่องค้นหาเลขข้อหรือภาษาไทยหนึ่งช่องต่อหัวข้อให้เปิดใช้เมื่อต้องการ ข้อมูลเดิมที่พิมพ์ไว้ยังอยู่และต้องตรวจจับคู่ก่อนส่งตรวจ ดู [ผลตรวจรายการอ้างอิง](reference-review/catalog-review.md) ได้เฉพาะเครื่องที่มีเอกสารโรงเรียน

เมนู **บันทึกข้อความ / คำขอ** สร้างคำขอทั้ง 6 ประเภทได้ทันที เชื่อมโครงการได้ทุกสถานะ หากยังไม่มีโครงการ บันทึกร่างก่อนได้แล้วเชื่อมก่อนส่งตรวจ การสร้างและส่งคำขอไม่อนุมัติโครงการหรือหักงบ พัสดุยังกันวงเงินเมื่อมีคำขออนุมัติและวงเงินโครงการเพียงพอ

ยังไม่เชื่อม Google Sheets หรือบริการแจ้งเตือนโทรศัพท์ รุ่นทดลองบน GitHub Pages เผยแพร่แล้วตาม [คู่มือ GitHub Pages](GITHUB_PAGES.md) ส่วนระบบ Node.js/SQLite เปิดในเครื่องหรือแชร์ลิงก์ชั่วคราวด้วยตัวเริ่มแชร์ด้านบน แบบเอกสารชนิดอื่นยังต้องเทียบกับต้นฉบับต่อ ส่วนหน้าจอและการตัดหน้าพิมพ์ของแบบโครงการยังต้องตรวจผ่านเบราว์เซอร์จริง

ดูสถานะล่าสุดใน [แผนดำเนินงาน](IMPLEMENTATION_PLAN.md) และที่มาของช่องข้อมูลใน [ผลตรวจแบบเขียนโครงการ](reference-review/project-form-review.md)

## ตรวจชุดทดสอบ

รันจากโฟลเดอร์โครงการด้วย Node.js 24 ขึ้นไป:

```powershell
npm test
```

ชุดทดสอบครอบคลุม dropdown และ checkbox การค้นหา/เปิดข้อย่อย/ยกเลิก การป้องกันรายการซ้ำ ข้อความพิมพ์จากสำเนาที่บันทึกไว้ การบันทึกและเปิดกลับหลังเริ่มเซิร์ฟเวอร์ใหม่ คำขอทุกประเภท สิทธิ์ การคำนวณงบ และประตูเข้าลิงก์แชร์ ชุดซอร์สโค้ดมีทั้งรายการอ้างอิงตัวอย่างและสำเนารายการสำหรับ GitHub Pages ส่วนการตรวจเทียบเอกสารโรงเรียนในเครื่องจะข้ามเมื่อไม่มีไฟล์รายการจริงในเครื่อง

การตรวจอัตโนมัตินี้ยังไม่ครอบคลุมภาพหน้าจอและการตัดหน้าจากเบราว์เซอร์จริง สคริปต์เสริม `scripts/extract_references.py` ใช้สำหรับตรวจเอกสารต้นฉบับในเครื่องผู้พัฒนา ต้องติดตั้ง Python พร้อม `pypdf`, `openpyxl` และ `Pillow` แยกต่างหาก การเปิดแอปและรันชุดทดสอบ Node.js ไม่ต้องใช้ Python
